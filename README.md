# 競輪シン — 真実の自動予想

> **最終目標：競輪のデータ収集・予想・直前オッズ分析・予想販売・車券自動購入・結果検証を一貫して自動化するシステムの構築。**

## 1. プロジェクト概要

「競輪シン」は、競輪の予想精度と期待値を検証しながら、最終的に以下の機能をつなぐことを目指す開発プロジェクトです。

1. 出走表、選手成績、ラインなどのレース情報を自動収集
2. 過去データを用いて着順確率・買い目の的中確率を推定
3. 締切前のオッズ変動を取得・分析
4. 期待値と資金管理条件に基づいて買い目・購入金額を決定
5. 予想コンテンツを自動生成・有料販売・配信
6. 対応が認められた投票サービスを通じて車券を自動購入
7. 的中率、回収率、収支を記録し、モデルを検証・改善

**現状（2026-10-31）：調査・要件整理段階。上記機能が完成・実装済みという意味ではありません。**  
予想精度、利益、投票サービスでの自動購入の可否について、現時点で保証・確定できるものはありません。

## 2. 競馬の自動予想・自動購入ツールから分かった事実

以下は2026年10月31日までに確認した公開資料の要約です。**裁判記録に残る実例、公式データ仕様、開発元による製品説明を区別**しています。

### 2.1 裁判記録に残る実際の自動購入

大阪地方裁判所の判決文には、JRAのA-PATと有料競馬予想ソフトを使った馬券自動購入の実例が記載されています。[資料1]

- 利用データ：JRA-VAN Data Lab.（判決文表記：Data-Labo）およびJRDBの競馬データ
- 自動取得：馬柱表示に必要な最新データ、馬体重、オッズ、払戻情報など
- 過去データ：10年以上の競馬データで条件別の的中率・回収率を検証
- 分析対象の例：前走着順、血統、騎手、枠順、性別、負担重量
- 採用した説明変数（ファクター）：約40項目。ただし**全40項目の内訳は公開されていない**
- 処理：独自の得点・抽出条件で買い目を決め、PAT口座残高とオッズに応じて購入金額を調整し、自動投票・結果記録を実施

これは**自動購入が現実に運用された証拠**ですが、現在の競馬全体での普及率や、オッズ急変の原因を示す証拠ではありません。

### 2.2 開発元が公開する競馬ソフトの機能

| ソフト・サービス | 公表されている情報・判断方法 | 自動購入 |
| --- | --- | --- |
| [TripleAutoBetSX Advance版](https://jra-van.jp/dlb/sft/lib/tripleautobetsx_ad.html) | 出馬表・直前オッズを取得し、設定条件で買い目抽出。見送り・収支打切り・結果集計にも対応 | 対応を公表 |
| [Victory PRO](https://jra-van.jp/dlb/sft/lib/vpro.html) | 単勝・馬連・馬単・3連複・3連単のオッズから推定シェア率、的中率、期待値を計算 | 対応を公表 |
| [KIWAME](https://jra-van.jp/dlb/sft/lib/kiwame.html) | JRA-VANのデータマイニング予想や外部指数を配合し、過去シミュレーションの条件に従う | 対応を公表 |
| [KEIBA SNIPER](https://www.sniper-japan.jp/pages/keiba.html) | 頭数・距離・グレード・競走条件・人気・オッズなどでレースと買い目を選別 | 対応を公表 |
| [競馬AIデータラボ](https://aidatalab.jp/keiba/system/) | 期待値で選別し、発走直前に馬券を自動購入すると説明 | 対応を公表 |

**注意：** 上表は提供元の公開説明で確認できた機能です。内部アルゴリズム、実際の全入力項目、販売実績、的中率・回収率は独立検証できていません。JRA-VAN上に掲載されていること自体が利益の保証を意味するものでもありません。

ここから確認できた代表的な方法は次の3つです。

- **過去成績・指数型**：競走条件や過去結果から得点・指数を計算する
- **オッズ・期待値型**：オッズから確率を推定する、または推定確率とオッズを比較する
- **直前条件・投票自動化型**：締切前の出馬表・オッズと条件を照合し、購入・見送りを実行する

これらは異なる方式であり、すべての製品がすべてのデータを使用しているわけではありません。

### 2.3 JRA-VANが公式に提供しているデータ

[JRA-VAN Data Lab. の公式仕様](https://jra-van.jp/dlb/ddata.html)では、次のような情報の提供が案内されています。[資料2]

| 時点 | 公開仕様で確認した情報 |
| --- | --- |
| 開催前 | 出走馬名表、出馬表、競走馬・騎手・調教師の情報、過去成績など |
| 開催当日 | 天候、馬場状態、出走取消、騎手変更 |
| 発走約60分前 | 馬体重、直前のデータマイニング予想 |
| 発売中 | 速報オッズ、5〜10分おきの時系列オッズ |
| 発売締切時点 | 速報票数 |
| 結果確定後 | 着順、払戻、確定成績 |
| 不定期 | 調教情報など |

**「データ提供元が取得可能にしている」ことと「特定の自動購入ソフトがそれを入力に使う」ことは別**です。また、締切時点の票数が提供されることは、投票者ごとの購入内容を取得できることを意味しません。

### 2.4 予想の有料販売・購入連携も存在する

- [競馬予想noteの全自動販売システムの出品](https://maclub.jp/note/576559)：出品者は、レースデータ取得 → AI予想 → 記事・画像生成 → note投稿・有料設定 → SNS告知まで自動化したと説明。[資料3] **出品者の自己申告であり、運用実績・売上は未検証。**
- [netkeiba「ウマい馬券」の買い目連携](https://info.netkeiba.com/?id=1136&pid=info_detail)：購入した予想の予算を変更し、買い目を投票へ連携できる機能を公式に案内。[資料4] **投票画面への連携であり、完全自動購入と同一ではない。**

「予想を有料販売する仕組み」と「車券・馬券を自動購入する仕組み」は別々に設計・検証する必要があります。

### 2.5 締切直前のオッズ変動について確定していること

- 公営競技の投票は、同じ買い目に資金が集中すると、その買い目のオッズ・払戻倍率が変化する仕組み。
- 直前オッズを取得して購入する競馬ソフトは実在する（例：TripleAutoBetSX）。
- 販売された同一予想を多数の人が購入すれば、オッズに影響する可能性はある。

**未確認：**「予想販売ツールの購入者が多数、締切直前に同じ買い目を購入していることが、オッズ急変の主因」という因果関係や、その影響の割合。公開オッズだけでは、大口1人と小口多数、手動と自動を識別できません。

また、**最終オッズを見てから、その時点では買えなかった有利なオッズで購入したものとして過去検証しない**ことが重要です。

## 3. 競輪にも実在する自動投票ソフト

[KEIRIN SNIPER（開発元サイト）](https://www.sniper-japan.jp/pages/keirin.html)では、競輪レースの条件指定・買い目設定・資金配分・見送り・打止め・シミュレーション・自動投票が説明されています。[資料5]

公表されている選別条件には、次が含まれます。

- ガールズ・A級・S級などのレース種別
- 車立て、開催グレード、シリーズ日程
- 買い目の人気順、オッズ範囲、フォーメーション
- 締切何分前にオッズを取得・投票するか
- 投票上限、損失上限、停止条件

**重要な区別：** 開発元は、このソフトを「利用者が指定した条件に基づいて投票を自動化するソフト」と説明し、**自動で予想を提供するソフトではない**と明記しています。競輪の自動投票ソフトの存在は確認できましたが、予測AI・自動販売・自動購入をすべて統合した製品の実在まで確認したものではありません。

## 5. システム構成案（未実装）

データ取得・保存 → データ品質検証 → 確率予測 → オッズ取得 → 期待値計算 → 買い目・資金配分 → [予想販売 / 車券購入] → 結果記録 → 評価・再学習

設計上は、次の機能を分離します。

- **予測エンジン**：レース結果の確率を推定する
- **市場評価エンジン**：その時点で取得したオッズと比較し、購入する価値・見送りを判定する
- **販売・配信エンジン**：公開用予想を生成・販売し、配信履歴を保存する
- **投票エンジン**：サービスの利用条件に適合する場合のみ、制限付きで購入処理を実行する
- **検証エンジン**：予測時刻・購入判断時刻・入手可能情報を保存し、バックテストと実績を比較する

的中率だけでなく、**回収率（払戻総額 ÷ 購入総額）・実収支・期待値の校正・最大損失・買い目ごとの購入可能オッズ・時系列テストでの再現性**を追跡します。これは今後の評価計画であり、達成済みの成績ではありません。

## 7. リスク・利用上の原則

- 予測・自動投票は**利益や的中を保証しない**。
- 車券の購入は20歳以上を前提とし、法令と各投票サービスの規約に従う。
- 公式APIや明示的に許可された連携方法を優先し、無許可の自動操作・アクセス制限の回避を前提にしない。
- 予想の有料販売では、データの商用利用許諾、表示内容、誇大な収益表示の防止を確認する。
- 購入上限、日次損失上限、停止条件、重複購入防止、障害時の停止を必須設計項目とする。
- 学習・バックテストで未来情報を混入させず、最終オッズを過去の購入時点のオッズとして扱わない。
- 自動購入の可否と販売の可否は**サービスごとに個別確認**する。

## 実装：レース前情報と選手別確定結果のデータ収集基盤 v0.1

`keirin_shin/` にSQLiteでデータを蓄積するPythonの取込基盤を実装しました。発走前の選手情報スナップショット、確定結果、払戻、収集時刻、提供元情報を保存し、重複排除・整合性チェック・収集漏れ検知・選手単位CSV出力ができます。

```bash
python -m unittest discover -s tests -v
python -m keirin_shin --db data/demo.sqlite3 ingest-dir examples
python -m keirin_shin --db data/demo.sqlite3 report --date 2026-10-31
python -m keirin_shin --db data/demo.sqlite3 export-riders --out data/demo_riders.csv
```

**現状：実際の競輪データ収集先は未契約・未接続。** `examples/` はすべて架空のテストデータです。許諾を得た提供元の接続までは全レースの実データ収集は開始されません。日次取得は `scripts/daily_sync.py` に対応しますが、配信元契約・フォーマット変換・永続的な実行環境の設定が必要です。

詳しくは [docs/DATA_PIPELINE.md](docs/DATA_PIPELINE.md) を参照してください。
